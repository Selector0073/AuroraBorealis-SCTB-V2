# Server Control & Monitoring & Configuration Management Panel

## 1. Мета
Легкий інструмент для розробників одиночок і маленьких команд, який перетворює дешевий VPS ($4-5/міс) на безпечне та кероване середовище для хостингу своїх проєктів. Без Docker і Kubernetes: сервіси працюють як звичайні нативні процеси, тому система майже не споживає ресурсів.

## 2. Проблема
- Наявні рішення потребують потужного (дорогого) сервера.
- Початківець змушений вручну налаштовувати безпеку, nginx, SSL і права доступу, і легко помиляється в конфігах.
- Через слабку безпеку сервер швидко компрометують боти.

## 3. Цільова аудиторія
Розробники одиночки, стартапи та студенти з власними сервісами (сайт, API, Telegram-бот) на найдешевшому VPS, які не хочуть вивчати DevOps і кібербезпеку.

## 4. Склад системи
**Арбітер на сервері (Rust + Bash + Python).** Одноразово розгортається setup-скриптом. Відповідає за:
- запуск, зупинку й перезапуск сервісів як нативних процесів;
- автоперезапуск після збою (з обмеженням частоти спроб) і автозапуск самого арбітера через systemd (`Restart=always`);
- моніторинг стану (працює / не працює / перезапускається) і метрик (CPU, RAM, диск, мережа, логи);
- сповіщення про збій, нестачу ресурсів і повторні перезапуски;
- деплой із GitHub або архіву та безпечне оновлення з автоматичним бекапом;
- автоматичне налаштування nginx (домен → порт сервісу) і випуск та продовження SSL-сертифікатів;
- керування конфігурацією сервісів (перегляд, зміна, застосування);
- локальний канал повідомлень від сервісів до клієнта.

**Клієнт** Керування кількома серверами з одного місця: список серверів і сервісів зі станом, метрики та логи, терміни дії SSL, сповіщення, відправка команд.

**Захищене з'єднання клієнт ⇄ агент.** Автентифікація клієнта, шифрування, мінімальні права арбітера. Протокол ще не визначено.

## 5. Сценарій користувача
**Старт:** є проєкт на GitHub, VPS з IP і паролем root, куплений домен.

1. **Встановлення клієнта** на свій комп'ютер.
2. **Додавання сервера:** «Додати сервер» → IP і пароль root → «Підключити». Програма сама налаштовує файрвол, nginx, захист і ставить арбітера. Через ~1 хв з'являється позначка «сервер готовий». Це одноразова дія.
3. **Прив'язка домену:** клієнт підказує, який A-запис створити у реєстратора, і перевіряє, чи він уже працює.
4. **Створення сервісу:** «Новий сервіс» → посилання на GitHub, команда запуску, домен → «Задеплоїти».
5. **Автоматично за ~1 хв:** завантаження коду, запуск, налаштування nginx, отримання HTTPS-сертифіката.
6. Користувач відкриває `https://домен` і бачить свій сайт.
